# Codex 教程

## 🔍 先澄清一个概念

**Codex** 这个名字有两代含义。老一代是 OpenAI 2021 年的代码补全模型（GitHub Copilot 早期的底座），早已退役；今天说的 **Codex** 是它在 2025 年 5 月“重生”后的形态——OpenAI 的**自主编程智能体**：你交给它一个任务（“修这个 bug”“给这个模块补测试”“评审这个 PR”），它在隔离沙箱里自己读代码、改代码、跑测试，最后带着改动建议和执行日志回来找你验收。当前由 GPT-5-Codex 系列模型驱动（2025 年 9 月首发，此后持续迭代）。

## 🤔 文科生为什么要认识它？

不是让你去写代码，而是让你**提前看懂“AI 员工”的工作方式**：派任务 → 等它独立完成 → 按产出验收 → 提修改意见再来一轮。这套动作和带一个实习生完全同构——区别只是它不知疲倦、按 token 计费。当你用自然人话描述需求的能力去“派活”，你就是那个不可替代的验收人。04 板块 Garry Tan 那期讲到的「AI harness 之争」（Salesforce / OpenAI Codex / Claude Code 抢智能体入口），抢的正是这个“派活儿的工作台”。

## 📚 Codex 简明四步学习法

### 第一步：选形态——云端、终端、IDE 三选一开始

Codex 有三个入口：**云端**（在 ChatGPT 网页/手机上直接派任务，沙箱里并行干活，最省心）、**CLI**（开源免费的终端智能体，自带 API key 即可用）、**IDE 扩展**（VS Code 系编辑器插件）。零基础建议从云端开始：打开 ChatGPT，连上 GitHub 仓库，直接用人话派任务。

### 第二步：写好 AGENTS.md——给“AI 员工”的入职手册

CLI 与云端都认项目根目录下的 `AGENTS.md`：把项目结构、代码规范、禁区写清楚。这份文件写得越像一份好的“新员工入职须知”，产出越稳——**会写交接文档的文科生，在这里是碾压级优势**。

### 第三步：权限分级，先从“只读”开始

CLI 提供三档权限：只读（read-only）/ 自动（可改工作区文件，外部操作需批准）/ 完全访问。第一次跑任何智能体都建议从只读开始，看懂它“想干什么”再逐步放权——这是使用一切 AI 智能体的安全底线。

### 第四步：让它开 PR，人做最终判断

Codex 与 GitHub 深度集成：在 PR 里 @ 它即可触发代码评审，也可以配 GitHub Action 进持续集成。记住分工——**它负责干，你负责判**：改动是否合理、测试是否真实覆盖、有没有偷偷绕过问题。

## 💰 费用与门槛（2026 年口径）

| 项目 | 情况 |
|------|------|
| 云端版 | 随 ChatGPT 订阅附带（Plus 约 20 美元/月起，更高档约 100–200 美元/月） |
| CLI | 开源免费，模型用量走 OpenAI API 计费（gpt-5.3-codex 约 1.75 美元/百万输入 tokens、约 14 美元/百万输出 tokens） |
| 前置条件 | 云端需要 GitHub 仓库；纯本地体验可只装 CLI |

## 🎯 入门学习计划

| 阶段 | 时间 | 学习重点 | 产出目标 |
|------|------|---------|---------|
| 阶段一 | 第 1 周 | 在 ChatGPT 里连一个自己的小仓库，派 3 个小任务（改文案、修样式、补注释） | 看懂它交回的改动说明与日志 |
| 阶段二 | 第 2-3 周 | 写第一份 AGENTS.md；学会只读/自动两档权限的切换 | 一个按你的规矩干活的智能体 |
| 阶段三 | 第 4 周起 | 让它接管重复性工作（依赖升级、批量改名、测试补齐）并开 PR | 每周至少省下一次“不想干杂活”的时间 |

## 📌 小结：核心要点

- **底层逻辑**：Codex 不是自动补全，是“派活-验收”式的 AI 员工；会用它的人赢在会派活、会验收
- **学习路径**：云端起步 → AGENTS.md 定规矩 → 权限分级 → 交 PR 由人拍板
- **能力检验标准**：能不能放心地把一件你讨厌的杂活整包交给它，并一眼看出它做得对不对
