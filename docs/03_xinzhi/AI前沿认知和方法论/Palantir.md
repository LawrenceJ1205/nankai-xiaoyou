# Palantir 方法论全拆解

> Palantir不是软件公司，而是一个“最顶级的IT咨询+极客工程+软件底座”的混合体。其灵魂是Ontology（本体论）方法论——把企业世界映射为可被系统识别的业务对象（订单、客户、资产等），并明确定义关系、规则、权限和可执行动作。

## 一、起源：对软件行业“原罪”的彻底反叛

Palantir的起点是911之后美国政府面临的致命困境——情报部门不是没有数据，而是数据全割裂了。CIA、FBI、国安局、军方各自拥有庞大信息库，但没有系统能把它们拼接在一起。

创始人的洞察是：解决方案不是一个报表工具，而是一个“决策系统”——前者告诉你昨天发生了什么，后者基于全局关联网络帮你决定新态势下该做什么。

## 二、核心技术：Ontology方法论的五步闭环

**第一步：经营对象**——从ERP、CRM、MES等系统抽取实体并去重，建立“唯一真相源”

**第二步：建立映射**——把分散在100个字段的业务数据精准映射到统一对象，不移动任何数据

**第三步：继承权限**——实现细粒度行级/列级权限继承，严格遵循原系统设置

**第四步：整体关联**——跨系统编织业务网络的认知地图，一个订单对应哪个发货单、谁审批、用了哪批物料

**第五步：定义动作**——将业务知识的终点定义为可执行Action，点击按钮调用CRM的cancel API，同步更新SAP库存

## 三、产品矩阵

- **Gotham**：面向政府和军队的决策操作系统
- **Foundry**：面向商业企业的“数据操作系统”
- **AIP**：AI引擎层，将大语言模型能力接入Ontology
- **Apollo**：底层持续交付平台

## 四、AIP的三大模块

1. **AIP Assist**：自然语言的“智能副驾”
2. **AIP Logic**：可视化的业务逻辑编排工具
3. **AIP Agent Studio**：可自主执行的智能体

## 五、交付模式：FDE

FDE（前线部署工程师）驻扎客户一线，拥有完整核心代码库访问权限。前线铺“碎石路”、总部抽象为“高速公路”。

## 六、核心竞争力

- 绑定“生死决策”的深耦合
- 续约率奇高，客户依赖以10年为单位
- Ontology的工程细节和业务经验不可复制
- “人+平台+AI”混合决策模式
