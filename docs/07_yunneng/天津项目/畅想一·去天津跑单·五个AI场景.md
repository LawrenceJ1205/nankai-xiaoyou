一行话：天津的主干场景已经被集团 IT、超算中心和头部厂商占住了；学生团队真正的生意不是「再做一套 AI」，而是落地最缺的那一公里——流程梳理、数据备料、评估集、驻场陪跑。这一公里便宜、必须蹲现场、还得有人指导，正好只有在读学生干得动。⚪

## 一、先修正三个前提

前提一，主干已被占，别去重造 PortGPT。天津 2026 年的公开口径已经很清楚：天津港 JTOS 上线（单桥效率 +10%、能耗 −8%），大型装卸设备自动化 88%，船舶直靠率 99.2%，集卡在港平均 14.2 分钟，PortGPT 用在智能理货与安全监管，津港通聚合 1.1 万家外贸物流企业与 3 万口岸用户；智慧海关已建水运集装箱智慧货场场景链的六个场景；东疆外代物流堆场闸口通行效率 +40%，无人叉车与巡检机器人上岗；海河医院全院本地化部署大模型、诊桌智能体铺到 20 个诊室；国家超算天津中心牵头的 AI 医院已在第五中心医院等十几个科室落地。🔵 凡是集团级、全院级、平台级的主流程，都轮不到学生团队。⚪

前提二，真需求不在技术方案，在没人愿意干的脏活。超算中心做 AI 医院的办法不是卖模型，是把工程师驻场进医院——与第五中心医院共建智能医院训练场，研发跟着医生的需求迭代。🔵 这条经验对学生极其有利：驻场、梳理、标注、建评估集，正是学生能干的，价钱也是甲方付得起的。⚪

前提三，区政府和国企不是客户，是场景持有人。它们很少直接为一个小工具立项，但能给三样东西：现场准入、业务口径、以及把你介绍给它的服务商与下属公司。真正掏钱的，往往是下属运营公司、园区服务商，或者被考核逼着降本的那一级。⚪ 所以第一次上门不要带 PPT，要带一个两周内能给人看的小东西。

## 二、五张场景卡

### 卡 1 · 港口与口岸

| 项      | 内容                                                                                 |
| ------ | ---------------------------------------------------------------------------------- |
| 场景持有人  | 天津港集团及其集装箱、散货码头公司；天津国际贸易与航运服务中心（上合口岸经济合作中心）；新港海关                                   |
| 真实流程切口 | 一是中小货代的单证复核：订舱、报关、装箱单三套口径对不齐，靠人眼核；二是异常与改单：甩柜、改配、滞港，靠电话；三是客服：重复问询吃掉大量人力；四是多式联运一单制对账 |
| 谁买单    | 中小货代自己（年费制）、口岸服务商、集团下属客服中心                                                         |
| 可交付档位  | A：单证复核、客服知识库、异常提醒　｜　C：放行、查验、涉密调度                                                   |
| 不要碰    | 海关放行判定、危险品申报结论、与船期或箱号相关的涉密数据                                                       |

### 卡 2 · 仓储与堆场

| 项      | 内容                                                                                                |
| ------ | ------------------------------------------------------------------------------------------------- |
| 场景持有人  | 东疆外代物流堆场、保税区化工物流企业、中小堆场与冷库                                                                        |
| 真实流程切口 | 一是入库验收：件数、破损、批次靠拍照加人记；二是库位与盘点：账实差异靠翻仓；三是危化品台账：品类、库存时长、超期预警（头部企业已用数字孪生示范，中小堆场没有）；四是回单与对账：纸质回单丢失是常态 |
| 谁买单    | 堆场运营方、货主（按票付费）、园区服务局的政策项目                                                                         |
| 可交付档位  | A：盘点差异核对、台账预警、回单识别加人工复核　｜　B：与仓储管理系统、闸口系统对接                                                        |
| 不要碰    | 自动化设备控制、消防与安全联锁                                                                                   |

### 卡 3 · 物流与车队

| 项      | 内容                                                                                 |
| ------ | ---------------------------------------------------------------------------------- |
| 场景持有人  | 保税区物流企业、平台型服务商、专线车队                                                                |
| 真实流程切口 | 一是驻场装卸与点检（车端 AI 已被占，车下几乎空白）；二是温控异常处置：报警之后谁怎么处理，没有闭环；三是回单核销：一张回单卡住一笔运费；四是司机端培训与事故复盘 |
| 谁买单    | 物流企业、货主（按降本分成）、保险（未遂事故）                                                            |
| 可交付档位  | A：回单核销、异常处置 SOP 助手、培训脚本生成　｜　B：硬件联动                                                 |
| 不要碰    | 车辆控制、驾驶行为判责                                                                        |

### 卡 4 · 医院（只做非临床）

| 项      | 内容                                                                                                                   |
| ------ | -------------------------------------------------------------------------------------------------------------------- |
| 场景持有人  | 海河医院、泰达国际心血管病医院、医大二院、第五中心医院、市肿瘤医院等（以区卫健委口径为准）                                                                        |
| 真实流程切口 | 一是出院随访（泰心 2026 年明确要建）：谁随访、说什么、异常怎么回到门诊；二是体检报告通俗解读；三是导诊与预问诊；四是病案质控的规则整理与评估集——不是做质控模型，是帮医院把「什么算漏项」写成可核对的清单；五是医护培训与演练脚本 |
| 谁买单    | 医院信息中心、体检中心、医联体牵头单位、区卫健委托管的平台                                                                                        |
| 可交付档位  | A：随访话术与工单、报告解读的科普层、导诊知识库　｜　B：对接医院信息系统　｜　C：任何诊断与用药建议                                                                  |
| 不要碰    | 诊断、处方、分诊判定、患者身份信息出楼；不碰医疗器械软件备案范围内的功能                                                                                 |

### 卡 5 · 洋行古建与街区

| 项      | 内容                                                                                                                                         |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------ |
| 场景持有人  | 和平区文旅局、天津市历史风貌建筑保护中心、天津市历史风貌建筑整理有限责任公司、五大道管理委员会、五大道文化旅游发展有限责任公司；解放北路运营主体                                                                   |
| 已公开的痛点 | 五大道 469 幢风貌建筑（占和平区 70.7%）、42.89 万平方米；市侨联 2026-07 调研直接点出「人气旺、体验浅、转化弱、协同难」与多头管理、权责交叉；区里下一步明确要用 AI 修复老照片、补全建筑历史信息、还原历史场景。🔵 方向已经写了，缺的是备料与试点。⚪ |
| 真实流程切口 | 一是史料结构化：四百余幢洋楼的图纸、档案、口述史分散在多家单位，先做成可检索的底库（这是所有 AI 展示的前置）；二是多语种导览与讲解脚本（入境游是明确考核项）；三是动线与客流：节假日拥堵与停车难；四是活动复盘：一年几百场活动，素材散落；五是保护巡查记录结构化         |
| 谁买单    | 区文旅局的项目经费、街区运营公司、招商与活动承办方                                                                                                                  |
| 可交付档位  | A：史料底库、多语种讲解、活动素材库、巡查台账　｜　B：与票务或客流系统对接                                                                                                     |
| 不要碰    | 建筑测绘与修缮方案（需资质）、未开放区域的拍摄与数据采集                                                                                                               |
| 现成入口   | 区里已与南开大学等 6 所高校搭实践展示平台，大龙邮局、桂林路 26 号院、张自忠旧居都做过活化设计与课题实践。🔵 照这条路走：先做课题，再谈项目。⚪                                                               |

## 三、可交付难度怎么判：七维打分

每维 0 至 2 分，满分 14 分。A 档＝90 天能交付；B 档＝六个月且必须甲方 IT 配合；C 档＝现在别碰。⚪

| # | 维度    | 0 分            | 1 分       | 2 分             |
| - | ----- | -------------- | --------- | --------------- |
| 1 | 流程看得见 | 全靠老师傅脑子，没有书面流程 | 有纸质单或局部系统 | 有系统日志与书面流程      |
| 2 | 数据拿得到 | 涉密或不可导出        | 可导出但要脱敏   | 可合法取用，接口现成      |
| 3 | 有人负责  | 找不到决策人         | 有对接人但无权限  | 有一名能拍板的中层       |
| 4 | 验收能说清 | 只能凭感觉          | 有粗略指标     | 有可测数字（耗时、漏项、返工） |
| 5 | 出错代价  | 停摆、罚款、伤人       | 返工、投诉     | 错了重来一次即可        |
| 6 | 现有系统  | 必须改造核心系统       | 需加接口      | 可旁路，不碰主系统       |
| 7 | 预算路径  | 必须公开招标         | 可走服务采购    | 部门自有小额经费        |

三条否决线，任一命中就退出，不要硬撑：第 2 维为 0（数据出不来）、第 3 维为 0（没人负责）、第 4 维为 0（验收无口径）。第 5 维为 0 的项目一律算 C 档——临床决策、危险品、海关放行、设备控制。⚪

## 四、三个配置套餐

| 套餐  | 周期   | 人                                                   | 钱                 | 交付物                       |
| --- | ---- | --------------------------------------------------- | ----------------- | ------------------------- |
| 诊断包 | 2 周  | 3 人 × 5 天现场跟班                                       | 0（交通自付）           | 一页《流程与数据可用性清单》＋七维打分＋一句话建议 |
| 验证包 | 6 周  | 1 名学生负责人（每周 20 小时）＋2 名同学＋1 名校友导师（每周一次）＋甲方 1 名 IT 对接 | 3 至 5 万（算力、标注、差旅） | 一个只读、人工复核的小工具＋一份验收记录      |
| 交付包 | 90 天 | 上面再加 1 名小友项目经理＋1 名校友企业借调的数据工程                       | 20 至 30 万         | 可日常使用的工具＋SOP＋交接培训         |

配置原则：一名学生只跟一个项目；校友导师不做技术兜底，只做「这家单位的话该怎么说」；甲方 IT 必须签字，否则不做。⚪

## 五、方向微调五条

1. 先读后写：第一版只做「读与提示」，不做「写与提交」，不碰任何会产生责任的按钮。
2. 先建议后决策：输出永远是「建议加依据加人工确认」，不自动执行。
3. 先内部后对外：先让内部人用来省时间，再谈对客户或游客开放。
4. 先异常后常态：常态流程已被系统覆盖，异常才是缝隙——改单、滞港、破损、超期、投诉。
5. 先人效后算法：验收物写成「这一步从 40 分钟到 8 分钟」「漏项从 6 项到 1 项」「返工率降一半」，不写准确率。准确率是厂商的语言，人效是甲方的语言。

## 六、九十天跑单剧本

| 阶段          | 做什么                               | 产出          |
| ----------- | --------------------------------- | ----------- |
| 第 0 至 2 周   | 选题：从五张卡里挑一个「有熟人、有痛点、出错代价低」的；写第一封信 | 一页纸意向       |
| 第 3 至 4 周   | 现场跟班：站在那个岗位旁边看两天，把每一步记成流程图        | 流程图＋七维打分    |
| 第 5 至 6 周   | 定边界：写清做什么、不做什么、怎么算成了              | 一页纸方案（甲方签字） |
| 第 7 至 10 周  | 做验证：小样本、只读、人工复核                   | 能演示的东西      |
| 第 11 至 12 周 | 验收与复盘：拿数字说话，写「下一步要不要做」            | 验收记录＋复盘一页   |

第一封信只要四句：我们是南开的学生团队，不是公司；我们在这个岗位看到这一步每天要花多少时间；两周内我们可以给你一个不要钱的东西，看完再决定；数据不出你的楼，我们到你现场做。

## 七、合规红线七条

1. 涉密不上网：港口调度、海关、口岸数据一律现场处理、结果不留存。
2. 医疗只做非临床：不做诊断、不做用药建议、患者身份信息不出院。
3. 国企不谈关系谈归口：走科技创新、数字化转型、团委实践基地的正规口子，留痕。
4. 学生安全与保险：进厂进院进工地前先报备，两人以上同行。
5. 不承诺效果：不签保底、不写「提升多少」，只写「本次实测」。
6. 知识产权先讲清：代码与数据归甲方，学生保留方法论文与作品集使用权。
7. 不当白手套：不代甲方写立项材料、不替甲方跑审批。
