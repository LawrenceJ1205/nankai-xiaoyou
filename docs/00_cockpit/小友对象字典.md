# 📖 小友对象字典（Ontology v0.1 · 草案）

> **一句话定位**：南开小友的"名词表 + 动词表"——把散在 276 篇 md、22 张表单、六个 skill 里的实体、关系、动作与权限，收进同一份可查、可维护的模型。
>
> **状态**：草案 v0.1 · 待主理人确认。**性质**：这是 Ontology 的"宪法层"——只定义名词、动词、关系与权限，**不改任何现有页面、不碰发布流程**。
>
> **依据**：Palantir 官方对 Ontology 的定义（把 **data ＋ logic ＋ action ＋ security** 四者合一、让人与 AI agent 操作同一套"名词 object/link ＋ 动词 action/function"的决策系统；它**不是**语义层/知识图谱），对照小友现状盘点后的本土化裁剪。Palantir 给跨国企业的重武器，到小友这个体量就是这一页字典 ＋ 一组约定。

**隶属**：🎯 00_cockpit · 顶层约定　｜　**读者**：主理人、共建者、AI agent　｜　**口径截至**：2026-11-23

---

## 〇、为什么要有这一页

小友不缺零件——对象、动作、闸门、权限全都有，只是**全是隐式的**：

| 症状 | 现在长什么样 | 显式化之后 |
|---|---|---|
| 同一实体多种叫法 | "骄人企业""企业卡片""校友掌舵上市公司"各叫各的 | 统一为 `企业（Company）` 一个对象 |
| 关系靠人脑互链 | 校友—企业—内容—活动散在正文的括号与链接里 | 命名关系，机器可查、可追溯 |
| 动作靠流程文档 | 收录/发布写在六个 skill 的说明里，靠人记着走 | 动词带输入、校验、写回点、审批 |
| 闸门靠脚本兜底 | 泄漏/断链/字数检查是发布前手工跑的脚本 | 升格为动作的内建前置函数 |

> 📌 **一句判断**：Ontology 的价值不在画一张知识图谱，而在于让每一次决策都有同一个对象可指、同一个动作可调用、同一套权限可依。

## 二、对象详解

### 1. 校友（Alumnus）

| 属性 | 口径 | 来源 / 备注 |
|---|---|---|
| 姓名 | 真名 | 表单必填 |
| 届别 · 院系 | 入学年级 ＋ 学院 | 企业卡片"创始人/核心校友"字段已大量沉淀 |
| 城市 | 常住城市 | 兴趣小组、校友会分区 |
| 身份标签 | 掌门人 / 投资人 / 在校生 / 共建者 / 召集大使 | 可多值；RACI 里"主理人本人＝返校召集大使"是固定身份 |
| 联络方式 | 手机 / 微信 | 🔒 隐私字段，仅内部版可见 |
| 联络授权 | 是否同意被联络 | 决定能否进入"邀约"动作 |

### 2. 企业（Company）

字段沿用 [板块 §收录字段](06_jiaoren/README.md) 的 **11 项硬约束**（各有字数上限）：主营赛道 ≤40 · 成立时间与总部 ≤45 · 当前阶段 ≤70 · 业务亮点 ≤60 · 创始人/核心校友 ≤120 · 核心产品与技术平台 ≤160 · 业绩与资本 ≤150 · 行业殊荣 ≤120 · 关联学院 ≤30 · 公开背书 ≤60 · 数据来源 ≤80。另有建议新增的排序字段 **身价/市值量级**。

三条填写纪律直接升级为对象写入规则：空值统一写 `——（未公开）` 或 `——（待核实）`；时间敏感内容（管线/订单/获奖）不进卡片、归专辑页；金额与市值必须标口径与截至日。

### 3. 内容（Content）

| 属性 | 口径 | 来源 / 备注 |
|---|---|---|
| 路径（＝ID） | docs 下相对路径 | 不带空格（历史坑：空格文件名会让链接裸出） |
| 体例 | 讲义 / 一手访谈照录 / 资料型扫描 / 案例 / 工作台 | 决定走哪条收录流程 |
| 信源级别 | **A** 一手原件 ／ **B** 可信转述整理稿 ／ **C** 仅作归纳、不单独采信 | 收录时必填；C 级只进归纳型页面 |
| 所属专辑 / 板块 | 专辑 README 路径 | 导航同步的依据 |
| BUILD | 该页上线的双入口 BUILD | 破缓存与回溯用 |
| 编者注 | 对勘发现、口径更正、待核项 | 照录不改正文，注里说明 |

### 4. 活动（Event）

类型取现有节奏：淘知精选十问（周一）、创业导师值班（周二）、校友新鲜事（周三）、投融资答疑（周四）、小鹅通直播（周五），外加返校召集、校庆、城市小组等临时活动。关键属性：时间、地点/通道、类型、负责人（→ 校友 ID）、沉淀产出（→ 内容 ID）。

### 5. 岗位（Job）

来自 `校友企业推荐岗位` 表单（短链 `iUR13k`），汇入 [允能南开人](07_yunneng/README.md)。属性：企业（→ 企业 ID）、城市、方向、发布日期、面向（在校生 / 校友）。反哺通道是"骄人握人、允能出岗位"的闭环。

### 6. 表单（Form）

22 张表单按板块归档，每张表的关键属性是：**采集目标对象**（这张表最终落到哪类对象上）——这是过去一直缺、却最该记的一列。

| 采集目标 | 代表表单（短链） |
|---|---|
| → 校友 | 共建者报名 `KRMvZL` · 返校召集 `U8lwtg` · 校友短视频 `xDa0g0` |
| → 内容 | 我的南开故事 `yPYC7g` · 淘知吧提问 `Ss66XU` · 九败一胜投稿 `t12d9c` |
| → 活动 | 兴趣小组意向 `aRlwy5` · 导师值班 `vT0qNX` · 值班导师认领 `f0oWjD` |
| → 企业 / 岗位 | 校友企业推荐岗位 `iUR13k` · 风投与私募投资人 `NwtCFD` |
| → 反馈 | 板块页底部建议 `okaiHT` · 捐赠图书意向 `bHzuau`（只登记意向） |

## 三、命名关系（Links）

| 关系 | 起点 → 终点 | 现有体现 / 用途 |
|---|---|---|
| `毕业于` | 校友 → 院系 | 企业卡片"关联学院"字段 |
| `任职于 / 创办 / 掌舵` | 校友 → 企业 | 企业卡片"创始人/核心校友"；决定"校友掌舵"口径 |
| `加入` | 校友 → 校友会 / 兴趣小组 | 四地校友会专区、兴趣小组表单 |
| `讲述` | 内容 → 企业 / 校友 | 案例页、语录集、掌门人故事 |
| `收录自` | 内容 → 信源 | 编者注里的来源与对勘记录 |
| `属于` | 内容 → 专辑 / 板块 | 导航同步的依据 |
| `沉淀出` | 活动 → 内容 | "每个对话都要被沉淀，否则就是裸奔" |
| `由…主持` | 活动 → 校友 | 值班排班、召集大使 |
| `来自` | 岗位 → 企业 | 岗位池反哺通道 |
| `采集→` | 表单 → 对象 | 上节"采集目标对象"列 |

## 四、动词（Actions）

每个动词写清四件事：**输入 → 逻辑校验 → 写回点 → 审批**。这是"闸门变函数"的落点——校验不再靠人记着跑，而是动作自带。

| 动词 | 输入对象 | 逻辑校验（内置函数） | 写回点 | 审批（RACI） | 现有雏形 |
|---|---|---|---|---|---|
| **收录** | 外部素材 | 信源分级 A/B/C、去重、内部词表闸门 | 新增内容对象 ＋ 导航三处同步 | 主理人 A | 新知/骄人收录 skill |
| **甄别** | 候选企业 / 嘉宾 | B/C 级核验、字段完整度与字数上限 | 企业对象字段补齐或淘汰红线 | 主理人 A | 企业收料—甄别—入库流程 |
| **发布** | 已 commit 的 md 改动 | 泄漏闸门、断链、目标含空格＝0、加粗配对、双入口 BUILD 同步、校友版剪枝 | 线上 md ＋ 版本日志 | 主理人 A | 六步发布 skill |
| **邀约** | 校友 ＋ 活动 | 身份、联络授权校验 | 表单报名记录 ＋ 召集状态 | 主理人 A ＋ R（本人即召集大使） | 返校召集报名 `U8lwtg` |
| **报名** | 校友 / 在校生提交 | 必填项、重复提交校验 | 表单对象新增记录 → 落到目标对象 | 金数据管理员 R | 22 张表单 |

## 五、逻辑与函数（Functions）

| 函数 | 挂在哪个动作 | 现有实现 | 升格方向 |
|---|---|---|---|
| 泄漏闸门 | 发布 / 收录 | `check_internal_leak.py` | 发布的硬前置，不过不发 |
| 断链扫描 | 发布 / 收录 | 内联扫描（断链、相对路径、目标含空格三个 0） | 同上；三个 0 写成硬断言 |
| BUILD 同步 | 发布 | `check_build_sync.py` | 双入口一致性硬断言 |
| 卡片字数校验 | 甄别 | `check_card_length.py` | 挂到"企业"对象的写入校验 |
| 信源分级 | 收录 | 人工判 A/B/C | 写成内容对象的必填属性 |
| 校友版剪枝 | 发布 | `check_alumni_dom.py` | 挂到发布动作的权限函数 |

> 📌 **昨天那次发布的教训**（2026-11-22）：文件名含空格导致链接裸出，根因就是"逻辑没绑在动作上"——靠扫描脚本兜底，而旧脚本正则漏了这一类。绑进"发布"动作的前置函数后，同类问题一次根治。

## 六、安全与治理

| 机制 | 现状 | 在 Ontology 里的位置 |
|---|---|---|
| 双入口 | `index.html` 内部版 ／ `alumni.html` 校友版，`00_cockpit` 整目录对校友隐去 | 对象级可见性：内部字段（联络方式、驾驶舱）默认不对外 |
| 分享链接 | 带 sharecode；微信内需复制到浏览器打开 | 分发权限与载体约束 |
| RACI | A 责任主（主理人）／ R 执行 ／ C 咨询 ／ I 知情 | 动作的审批位；"谁批"写进动词表 |
| 隐私字段 | 联络方式、联络授权 | 字段级标记，随双入口自动过滤 |

> ⚠️ **不要上数据库、不要建图**：md 本身就是数据源，本页是"约定层"，不是新基建。最大的收益在阶段 5——AI 现在读的是散装 md，有了对象模型才拿得到"校友—企业—内容—活动"的结构化世界，能回答"天津做生物医药的校友掌舵企业有哪几家、各对应哪篇案例"这类问题，且带出处、带权限。

## 八、维护规则

1. **新增对象 / 字段**：先改本页（字典是宪法），再动具体页面；字段口径变更须同步本页与板块 README。
2. **ID 一经分配不复用**；内容对象的 ID 即路径，故文件改名等于 ID 变更，须走全库引用同步 ＋ 旧路径占位页。
3. **文件名禁空格**：新增内容一律用连字符或全角连接号，不用半角空格（历史坑，见 §三备注）。
4. **动词新增**：必须写全"输入—校验—写回—审批"四格，缺一格不予登记。
5. 本页属内部页，随双入口机制对校友隐去；**不单独对外发布**。
