# 《精益创业》埃里克·莱斯 · 把创业变成可验证的实验

> **一句话定位**：创业不是执行一份完美计划，而是**在极端不确定下，用最小成本做最多的可验证实验**。这本书给“科学创业”提供了底层循环——后面所有中文创业方法论，几乎都从这里长出来。

## 📌 30 秒摘要

- **主循环**：想法 → 开发 → 测量 → 认知 → 新的想法。创业就是**转这个圈**，圈转得越快、越便宜，成功概率越高。
- **MVP**：不是“功能少的产品”，而是**为验证核心假设而设计的最小实验装置**。
- **经证实的认知**：唯一算数的进度指标——不是做了多少功能，而是**学到了什么被数据证实的东西**。
- **三个可衡量的里程碑**：MVP 上线 → 产品与市场契合 → 增长引擎启动。
- **两句话**：宁可“**快速地失败、廉价地失败**”，也不要“昂贵地失败”。

## 一、这本书解决什么问题

⚪ **编者归纳**。莱斯指出的困境是：创业者当时**手里只有两套工具**——

1. **传统管理**：依赖长期稳定的运营历史做预测。但新创企业**没有历史**，条件不具备；
2. **英雄式直觉**：靠创始人拍脑袋。于是大量团队**花半年、烧几百万打磨一个自认为完美的产品**，推到市场后发现“用户不需要”。

两者都是“**昂贵地失败**”。莱斯要给的，是一套**能在没有历史数据的情况下管理创新**的方法——把“精益生产”的思路搬到创业现场：**小批量、快速反馈、消除浪费**。

## 二、核心框架（颗粒度）

### 2.1 主循环：开发—测量—认知

| 环节 | 做什么 | 关键动作 |
|---|---|---|
| **开发** | 把想法变成产品的最小形态 | 只做体现核心价值的部分，**不在细枝末节上耗费精力** |
| **测量** | 用真实用户行为检验 | 看**可执行指标**，不看总量数字 |
| **认知** | 判断假设成立与否 | 成立 → 继续；不成立 → **转型** |

> 🔑 **一句话记住**：这个循环的产出**不是产品，是认知**。产品只是获取认知的工具。

### 2.2 最小可行产品（MVP）——不是“半成品”

⚪ 最常见的误读，是把 MVP 当成“功能被砍掉的残缺版”。**莱斯的定义更严格**：

- MVP 是**为了验证一个具体假设**而设计的**最小实验装置**，它甚至不必是“产品”；
- 判断标准不是“功能是否完整”，而是“**跑完这个实验，我能不能判断假设真假**”；
- 因此 MVP 的形态可以是：一段演示视频、一个落地页、一次人工代做的服务、一块纸板。

> **⚠️ 与《里程碑》的呼应**：许楚书里“AI 智能工牌”用**纸板模型 + 真人背后举牌提词**替代 500 万硬件研发，就是这个定义最干净的示范（详见 [《里程碑》](04_chuangye/创业必读书/里程碑.md)）。

### 2.3 经证实的认知：唯一算数的进度

莱斯的核心主张是**重新定义“进度”**：

| 假进度（不算数） | 真进度（算数） |
|---|---|
| 做了多少功能、发了多少版 | **验证了多少条关键假设** |
| 累计注册用户、累计下载量 | 同期群的行为变化 |

> **为什么这个替换很关键**：只有“经证实的认知”能回答创业者真正的问题——**继续投入，还是转向？**

### 2.4 创新核算：三个可衡量的里程碑

这是全书最可操作的一段。莱斯要求团队为进展**造一套财务式的账**：

| 阶段 | 里程碑 | 判断依据 |
|---|---|---|
| ① | **建立基准线** | MVP 上线，拿到第一组真实数据 |
| ② | **调校增长引擎** | 找到产品与市场契合（PMF），同期群指标改善 |
| ③ | **转型或坚持** | 数据支持继续投入，还是必须换方向 |

> 🔑 **关键**：这三步是**顺序推进**的。团队最常见的错误是**跳过②直接冲③**——产品还没契合，就砸钱买增长。

### 2.5 虚荣指标 vs 同期群指标

| 类型 | 例子 | 问题 |
|---|---|---|
| **虚荣指标** | 累计注册数、总下载量、页面总访问量 | 只涨不跌，**永远显示“我们很好”**，无法指导决策 |
| **同期群（cohort）指标** | 按获客批次分组看留存 / 转化 / 付费 | 能看出**新版本到底有没有让事情变好** |

⚪ **为什么必须按“同期群”看**：因为总量在长，几乎所有改动都“看起来有效”。只有把用户按批次切开，才能看出真实变化。

### 2.6 三个增长引擎

莱斯把可持续增长归结为三种可计算的引擎：

| 引擎 | 动力来源 | 核心指标 | 典型场景 |
|---|---|---|---|
| **黏着式** | 老用户持续回来 | 留存率 / 流失率 | 订阅制、工具类产品 |
| **病毒式** | 老用户带来新用户 | 病毒系数（每个用户带来几人） | 社交、协作类产品 |
| **付费式** | 花钱买增长 | 获客成本 vs 用户终身价值 | 电商、消费类 |

> **判断“可以踩油门”的条件**：付费式引擎要求单位经济模型成立；病毒式要求病毒系数可持续大于阈值；黏着式要求留存率稳定在高位。**引擎不成立时加速，只会加速烧钱。**

### 2.7 转型（Pivot）：十种转向

**转型 = 保持一半、改变一半**的**结构化方向调整**（不是推倒重来）。莱斯整理了十种常见类型：

| # | 转型类型 | 改的是什么 |
|---|---|---|
| 1 | 放大转型 | 把原产品的**某个单一功能**做成整个产品 |
| 2 | 缩小转型 | 把整个产品**缩成一个大产品的某个功能** |
| 3 | 客户细分转型 | 产品不变，**换一类用户** |
| 4 | 客户需求转型 | 用户不变，**换要解决的问题** |
| 5 | 平台转型 | 从“做产品”转为“**做平台 / 生态**”（或反之） |
| 6 | 业务架构转型 | 改变**价值创造与交付**的组织方式 |
| 7 | 价值获取转型 | 改变**怎么赚钱**（定价 / 变现模式） |
| 8 | 增长引擎转型 | 从一种增长引擎换到另一种 |
| 9 | 渠道转型 | 换一个**获客与交付渠道** |
| 10 | 技术转型 | 用**新技术**实现同一件事（常为降本或提速） |

> **⚠️ 与《里程碑》的四字诀对照**：转型方向选哪个，本质在回答“痛 / 频 / 量 / 价”里**哪一项判断错了**。

### 2.8 小批量与“五个为什么”

- **小批量（small batches）**：一次交付一点点，**反馈来得快、废品损失小**。莱斯用制造业的例子说明：批量越大，问题发现得越晚，返工越贵。
- **五个为什么（Five Whys）**：每出现一个问题，**连续追问五次原因**，直到触到流程与制度的根因——而不是停在“某个人操作失误”。

## 三、可上手的工具 / 检查清单

### ✅ MVP 设计检查表

| # | 自问 |
|---|---|
| 1 | 这个 MVP 要验证的**具体假设**是什么？一句话能不能说清？ |
| 2 | 如果假设被证伪，我**会做什么改变**？（答不出，说明实验不该做） |
| 3 | 有没有**更便宜**的方式拿到同样结论？（视频 / 落地页 / 人工代做） |
| 4 | 多久能拿到结果？（**时间越长，越该再砍一刀**） |
| 5 | 我用什么指标判断真假？**这个指标会不会只涨不跌**？ |

### ✅ 进度复盘四问（替代“这个月干了啥”）

1. 这个周期我们**验证了哪几条假设**？
2. 哪条假设被**证伪**了？我们因此改了什么？
3. 数据里有**同期群层面的改善**吗？
4. 下一步是**坚持**还是**转型**？依据是哪条数据？

## 四、与其他两本的分工

| 书 | 负责回答 | 不负责 |
|---|---|---|
| **《精益创业》** | **怎么科学地试**——循环、MVP、创新核算、转型 | 中国本土的商业场景细节；**往哪个方向积累** |
| [《里程碑》](04_chuangye/创业必读书/里程碑.md) | **在中国怎么做**——五步里程碑 + 本土案例 + 工具包 | 不重讲 MVP 的原理（原书直接把 MVP 收进“产品定义”） |
| [《纳瓦尔宝典》](04_chuangye/创业必读书/纳瓦尔宝典.md) | **杠杆压在哪**——专长、杠杆、责任、判断力 | 不给实验方法，也不给五步流程 |

> **师承关系（值得知道）**：《里程碑》作者许楚在自序中明确写过——史蒂夫·布兰克是《精益创业》作者埃里克·莱斯的导师，而布兰克的《创业者手册》是**整个精益创业理论的实操基石**。也就是说：**《创业者手册》→《精益创业》→《里程碑》**，是一条清晰的方法论传承线。
